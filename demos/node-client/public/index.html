Watching grpc-ebcdic decode

One HTTP request carries the file up while decoded rows come back down, the same shape as the gRPC call underneath. A row lands the moment its record's last byte arrives, which is why rows show up before the upload bar fills. Slow the upload to watch it happen.

The throttle delays the upload only, to make streaming visible on a file that would otherwise finish inside one animation frame. The decoder never waits for anything but bytes. Try statement.ebc to see two record schemas routed by a one-byte type prefix into two tables, and sales-week.ebc to see a COBOL OCCURS 7 arrive as seven packed-decimal columns. Fixtures are real cp037 bytes; regenerate them with demos/sample-data/generate.py.
